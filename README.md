当当前节点可用时尽量不切换；明确故障时安全容灾；同一服务在多个节点出现同类异常时，不把网站故障错误归因给节点。

它面向使用 Clash Verge Rev 或 Mihomo 的 Windows 用户：不要求机场采用固定节点命名，不修改 Clash 配置文件，不上传遥测，也不提供或销售代理节点。

| 稳定优先 | 订阅兼容 | 本地可信 |
| --- | --- | --- |
| 一次慢响应或一次高分不会触发主动切换 | 支持 `proxies`、`proxy-providers` 和混合订阅 | 不读取浏览历史，不上传订阅、日志或节点数据 |
| 性能候选需要 5 次、30 分钟、95% 成功率历史 | 不按香港、台湾、日本等地区名称过滤 | 只操作现有代理组选择，不接管订阅 |

## 三步开始

1. 从 [Releases](https://github.com/tejamanilannya593-arch/clash-compat-monitor/releases/latest) 下载并解压完整发布包。
2. 在 Clash Verge Rev 中启用包内的 `clash/enhancement.js`，应用配置后运行 `Diagnose.cmd`。
3. 运行 `Install.cmd`，选择长期需要的服务，然后关闭窗口让程序在托盘后台工作。

首次使用、升级和卸载细节请阅读 [QUICKSTART.md](QUICKSTART.md)。诊断只检查本机配置标记，不读取或输出订阅内容。

## 它如何避免误切

- 当前节点明确失败时，先快速复检同一服务，避免一次超时直接触发切换。
- 当前节点和两个近期备用节点出现同类服务异常时，熔断该服务 10 分钟；其他服务继续检测，但这次异常不计入节点历史。
- 当前节点仍可用时，只有持续偏慢且候选具备稳定历史、优质延迟和足够提升，才允许性能寻优。

## v0.6.0 能力与策略

- 当前节点的明确服务失败经快速复检确认后，会在两个近期备用节点上只复检同一服务；当前节点与两个备用节点均出现同类异常时，才判断为服务端公共异常。
- 公共异常触发 10 分钟服务熔断：继续检测其他所选服务，但该异常不归因于节点、不写入节点失败历史，也不因此切换节点；到期后自动恢复完整检测。
- 备用不足、任一备用通过或失败类型不同，都不会形成公共异常共识，程序继续沿用原有的连续失败确认和安全容灾流程。
- 设置页新增可选的“JMComic 网页”检测，固定测量 `https://18comic.vip/` 的 HTTP 响应延迟；默认不勾选，只有用户主动启用才会发起请求。
- JMComic 正常页面和重定向视为可达；Cloudflare 验证页只标记“仅确认可达”，明确的 `Restricted Access!` 返回才判为地区/IP 受限。
- 增强脚本同时支持顶层 `proxies`、`proxy-providers` 和两者混合的订阅结构；单节点订阅也会生成可用的统一组和探测组。
- 订阅顺序变化或只增删少量节点时保留已积累的稳定历史；候选集合明显不同或检测服务变化时创建隔离历史，避免不同机场的同名节点直接共用结论。
- Clash 重载后，30 分钟内验证过且仍存在的节点可进入现场复检；只有复检通过才会恢复，不会仅凭旧记录切换。
- 隐私安全日志增加候选数量、订阅历史延续结果、首次服务失败与快速确认结果；节点仍仅以短哈希记录。
- 0.4.0 增加稳态延迟策略：当前节点最近 3 次综合响应的中位数必须持续超过 800 ms 才启动性能寻优；一次慢响应不会触发切换。
- 性能候选最近 5 次响应必须同时满足中位数不超过 500 ms、P95 不超过 800 ms、波动不超过 150 ms；本轮任一所选服务超过 1000 ms 也不会用于性能切换。
- 详情页显示当前综合响应及“优质、可用、偏慢、质量较差”等级；历史推荐页显示严格成功率、样本跨度和寻优资格进度。
- 0.3.3 增加“足够好就不切换”的延迟门槛：当前综合 HTTP 响应不超过 500 ms 时保持现有节点；性能寻优目标也必须不超过 500 ms。
- 0.3.2 收紧性能寻优：一次高分不再触发主动切换，候选必须满足稳定历史门槛；性能切换首次明确失败时会优先复检旧节点并安全回退。
- 0.3.1 优化开机体验：当前节点检测通过后立即显示正常，备用准备继续在后台运行；明确失败会立刻复检失败服务，确认后最多检查 4 个候选，找到首个合格替代即可进入切换前复检。
- 状态页显示当前节点的来源，区分开机沿用、自动切换、自动回退和检测发现的外部变更。
- 发布包提供只读环境诊断和双击安装入口；“运行统计”显示本次启动的检测次数、资源占用和有限口径的探测正文量，不自动上传。
- 检测期间显示当前阶段并保留最近结果与真实检测时间；失败和证据不足不再显示为“运行正常”。
- AI 登录页、验证码页单独显示“仅确认可达”，不代表对话或生成已验证。
- 备用节点延迟筛选每轮最多 12 个，轮换覆盖订阅；90 秒后不再启动新的兼容性扫描，110 秒后不再启动速度采样，为切换前复检留出时间。总预算约 3 分钟，在请求间检查退出，单次进行中的请求仍需等待自身超时。
- 检测到较大流量时，健康连接暂缓备用扫描、速度采样和性能优化切换；当前连接明确异常时仍允许寻找替代节点。
- 自动切换、重载恢复和手动恢复上一个节点均增加实时复检；目标失败或用户已改变选择时保留当前连接。
- 暂停会要求本轮检测退出，并保留现有检测结果；正在进行的网络请求结束后生效。
- 支持高 DPI 清晰渲染，内置多尺寸蓝色节点盾牌图标。
- 首次运行勾选常用服务；可选择 Google、GitHub、ChatGPT、Gemini、Steam、Discord、Spotify、Epic 和 JMComic 网页。
- 后台只对用户选择的服务建立兼容门槛，并显示各服务的 HTTP 响应时间；不读取浏览历史，也不扫描当前网页。
- 综合 HTTP 响应不超过 500 ms 视为优质，501–800 ms 为可用，801–1500 ms 为偏慢，超过 1500 ms 为质量较差；超时或明确服务失败才判为不可用，延迟偏高本身不会触发容灾。
- 微信、B站等国内流量沿用 Clash 直连规则；Steam 游戏内容下载直连。
- 地区名称不决定兼容性。台湾、香港、日本、新加坡等标签均不自动加分或排除。
- 候选节点来自 Clash 的结构化叶节点对象，不要求旗帜、地区名或固定倍率格式；倍率无法解析时仍会参与实测，只是不做确定的成本加减分。
- `Compatible` 表示后台可可靠验证的项目通过；`BasicCompatible` 表示 AI 页面、登录或验证链路可达但账号内功能未验证；`Unknown` 表示证据不足。
- 当前节点可用时，只有最近 3 次中位响应超过 800 ms 才考虑性能寻优。候选必须已累计至少 5 次、跨度至少 30 分钟且成功率不低于 95% 的同订阅与服务组合历史，并满足五次延迟分布、本轮单服务上限、分数至少提升 20% 和当前节点已持有 10 分钟，才会主动切换；完全断网和已确认故障的容灾接管不受这些性能门槛限制。
- Clash Verge 自动更新订阅并应用配置后，程序会恢复 30 分钟内验证成功且仍存在的最近稳定节点；普通手动切换不会被覆盖。
- 当前节点连续失败时，完整兼容和基础兼容节点都可以在本轮重新验证后参与接管，未知或处于冷却期的节点不会被采用。
- 单实例运行，日志最多 1 MiB，状态历史最多 256 KiB；一次吞吐刷新最多 5 MiB。
- Mihomo 命名管道的连接、写入和读取都有期限，核心异常不会让一次检测永久挂起。

## 自动保障

- 最多维护两个备用节点，验证记录 10 分钟有效；需求变化或复检失败即失效。正常流量下约每 5 分钟补充或刷新，下载活跃时延后。故障时优先复检已有备用。
- 启动即检测当前节点并开始准备备用，不等待长期记忆积累。首轮无法找到备用时继续分批探索，不保证所有订阅都有合适节点。
- 自动切换后保存观察状态，重启仍可继续；30 秒后再检测。性能优化切换后第一次明确服务失败就复检旧节点，旧节点通过则立即回退；仅响应慢时仍需连续两次慢于原节点 25%，且旧节点当前响应快于目标 20% 才回退。因当前节点故障进行的容灾切换仍需新节点连续两次失败才请求回退。
- 用户已更换节点时取消自动回退。观察结束后暂停性能寻优 30 分钟，明确故障仍可恢复；未知验证结果不当作失败。
- 正常连续检测后间隔由 1 分钟延长到 3 分钟，异常或观察期为 30 秒。这里保障的是后台服务端点探测，不代表所有网页或账号功能一定正常。

## 日常使用

“切换记录与推荐”可查看最近 300 条确认成功的切换和检测发现的外部变更，以及当前订阅、服务组合下的历史推荐。首次启动建立基线，不补造历史。两轮检测之间的多次外部切换无法全部追溯。

记忆保存在本机 `state/experience.json`，最多 256 个节点与需求组合条目，30 天淘汰。界面推荐需至少 3 次观察、跨度 10 分钟，最近一次通过且 7 天内有检测；性能寻优自动切换采用更严格的至少 5 次、30 分钟跨度和 95% 成功率门槛。先用历史筛选，再实时复检。排名按稳定性、响应、抖动和 24 小时内真实速度采样综合计算，历史只占自动切换分数的 20%，仍执行其他切换门槛。数据来自后台探测，不是浏览记录或网页加载统计。

首次启动会打开设置窗口。保存常用服务后，Monitor 缩到系统托盘并长期自动运行；正常状态不会弹窗。双击托盘图标可查看实际节点、最近决策、下一次检测时间和各平台实测结果，也可立即复检、暂停或恢复自动优化，并在一次自动切换后恢复上一个节点。

常用服务和自动模式设置保存在本机状态目录的 `state\preferences.state`，不会上传。

关闭详情窗口不会退出守护。需要退出时使用托盘菜单或详情页的“退出节点守护”。二次启动 EXE 会唤起已经运行的详情窗口，不再静默显示为“打不开”。Clash 的“🌐 统一稳定节点”组仍显示当前真实叶节点，节点清单和手动选择继续由 Clash 管理。

## 要求

- Windows 10/11
- Clash Verge Rev 2.4.5，Mihomo 内核
- 已有可用订阅；本项目不提供代理节点
- 构建源码需要系统自带 .NET Framework C# 编译器和 Node.js

## 配置 Clash

在 Clash Verge Rev 中把 `clash/enhancement.js` 作为 JavaScript 增强脚本启用并重新生成配置。脚本会从显式节点和 provider 中发现候选，并创建：

- `🌐 统一稳定节点`：实际使用的统一节点组
- `🧪 兼容性探测`：独立探测组
- `127.0.0.1:7896`：仅本机可访问的探测监听器

确认代理页面能看到以上两个组后再安装监控器。安装脚本不会自动修改订阅或重启 Clash。

powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1

## 安装与升级

解压发布包后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

后续版本使用 `scripts/upgrade.ps1`。脚本先备份旧程序、状态和日志，只替换监控器，不重启 Clash；Clash 关键配置哈希发生变化时会回滚。

运行状态同时写入 `%LOCALAPPDATA%\ClashCompatibilityMonitor\current-status.txt`。Clash 首页选择“统一稳定节点”代理组，即可直接看到实际节点名称。

## 卸载

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall.ps1
```

卸载会停止本项目进程并删除本项目在 `%LOCALAPPDATA%` 下的目录和启动快捷方式，不修改 Clash 配置或订阅。

## 限制

无登录后台检测无法证明 ChatGPT 对话或 Gemini 生成等账号级功能一定可用，也无法消除网站自身故障、账号风控或代理供应商拥堵。界面中的响应时间来自轻量 HTTP 探测，不代表网页渲染、AI 生成或游戏服务器延迟。JMComic 域名可能变更，JMComic 检测按用户选择固定访问 `18comic.vip`，若该域名失效则需更新程序。Steam 游戏和下载仍服从 Clash 现有直连规则。v0.6.0 是本地优先版本，不上传遥测数据。配置重载恢复依赖运行时 IPv6 覆盖重新出现这一信号；若用户的 Clash 配置始终强制关闭 IPv6，程序会保留常规故障检测，但可能无法识别该次重载。
