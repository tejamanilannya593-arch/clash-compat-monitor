# ClashCompatibilityMonitor v0.7.0-preview.9

## 本次变化

- 定时性能寻优不再永远只检查 Mihomo 实时延迟最低的节点。
- 每轮候选由最多 5 个实时低延迟节点、2 个近期历史高质量节点和 1 个未充分测试节点组成。
- 扫描顺序交错安排实时、历史和探索来源，让探索节点能在“找到 3 个合格候选即停止”之前获得真实检测机会。
- 重叠候选会去重；某类不足时按本轮实时延迟补位，总数仍不超过 8 个。
- 候选来源只影响测试对象和顺序。最终仍以本轮真实服务响应 P75 为主、Mihomo 实时延迟为同分处理依据。
- 目标仍须通过全部已选服务完整验证、收益门槛、30 秒确认、切换预算、观察和安全回退。
- HardFailure 与 SevereDegradation 的容灾流程不使用探索规划，继续严格按照本轮实时延迟快速处理。
- Decision Trace 会记录各来源数量和安全节点指纹，不记录节点原名或原始出口 IP。

## 保持不变的边界

- 所有叶子节点的 Mihomo 延迟仍只并发检测一次，单节点上限 2500 ms。
- 单候选快速服务验证上限仍为 2 秒。
- 最多检查 8 个候选，找到 3 个合格候选后停止。
- 历史数据不能覆盖本轮真实检测结果。
- 程序只操作代理组选择，不修改 Clash 配置或订阅文件。

## 升级与验证

使用本版本文件夹内的 `scripts\install.ps1` 从 preview.8 升级。安装后应确认：

- 产品版本为 `0.7.0-preview.9`；
- 只有一个守护进程；
- 开机启动快捷方式指向当前安装目录；
- 至少两个 `cycle trigger=scheduled` 自动周期无需点击“立即复检”即可出现；
- 安装前后的 Clash 配置和订阅文件 SHA-256 完全一致。
