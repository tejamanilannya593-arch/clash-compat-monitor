# v0.7.0-preview.8 — 独立出口事故证据

本预览版修复“多个节点名称实际共用同一出口时，被误判为公共服务事故”的问题，并把原始检测事实与节点健康归因正式分开。

## 主要变化

- 公共服务事故必须由当前节点和两个备用节点的三个不同实际出口共同证明。
- 三个出口的 ASN 都可用时，至少需要两个不同 ASN；ASN 不完整时，至少需要两个不同国家。
- Cloudflare trace 继续作为出口指纹和国家的权威来源；ASN 通过同一候选代理从 IPWho 补充，并缓存 60 分钟。
- IPWho 返回的出口必须与 Cloudflare 的带密钥指纹及国家一致，否则 ASN 证据被拒绝。
- 原始出口 IP 只在内存中参与带密钥指纹计算，不保存、不记录、不显示。
- 每个服务结果明确区分 `Success`、`Failure` 和 `Unknown`，同时单独记录是否计入节点健康历史。
- 服务熔断不会改写真实失败；界面和诊断仍显示失败，仅将对应服务排除出健康、质量、备用和稳定率历史。
- 共识日志只记录不同指纹、国家和 ASN 的数量及拒绝原因，不记录原始 IP 或完整节点名。

## 保留的安全策略

- 健康状态最长 60 秒自动复检，故障和切换观察阶段 30 秒复检。
- 当前节点继续检测全部已选服务；恢复和回退验证仍覆盖全部服务。
- 性能切换继续要求至少改善 20% 且减少 200 ms，近期切换后提高到 30%。
- 十分钟最多自动切换 2 次、三十分钟最多 4 次；明确硬故障仍可优先恢复。
- 安装器和运行程序不修改 Clash 配置或订阅文件。

## 升级

preview.8 使用独立版本目录和压缩包，不覆盖或重新发布 preview.7。安装脚本会保留状态与日志、创建升级备份、执行 Mihomo 自检，并重新建立开机自启动快捷方式。
