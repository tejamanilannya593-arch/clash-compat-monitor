# v0.7.0-preview.3 — 更快、更保守的质量判断

- 同一节点的所选服务改为并发探测，单个慢服务不再让整轮逐项累加等待；失败归因仍按服务配置顺序确定。
- “综合响应”由简单平均值改为 P75：不再让少数快速响应掩盖明显慢服务。最慢服务超过 2000 ms 时直接显示服务名称和延迟。
- 延迟等级调整为：不超过 300 ms“优秀”、不超过 500 ms“良好”、不超过 800 ms“可用但偏慢”、超过 800 ms“较慢”。
- AI 入口可达但账号或真实对话未验证时显示“基础连接可用”，不再在后台补齐备用节点期间误显示“正在检测”。
- 性能寻优候选的历史响应要求收紧到 P75 中位数不超过 500 ms；5 次/30 分钟/95% 成功率、连续故障确认和切换后回退要求保持不变。

网页入口或登录链路可达仍不代表账号和真实对话一定可用；本版本不会按节点地区名称排除候选。
