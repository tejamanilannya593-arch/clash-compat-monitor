# Clash 重载安全故障接管 v0.1.1 设计

## 背景与根因

Clash Verge Rev 每 240 分钟自动更新远程订阅。更新会重新生成并应用运行时配置，自定义的“统一稳定节点”选择器可能回到候选数组第一项。当前配置已经启用 `profile.store-selected: true`，但实机日志证明它不能可靠保存增强脚本生成的选择组状态，因此不能把它视为唯一保护。

第二个问题发生在故障接管：扫描器把 ChatGPT Cloudflare 验证页和 Gemini 登录页记为 `BasicCompatible`，质量排名也把该等级当作可用；但 `FailoverController` 只允许 `Compatible` 作为替代节点，导致已有可用替代节点时仍显示“等待安全替代”。

## 目标

- 保留正常订阅自动更新，不通过延长更新时间掩盖问题。
- 配置重载后恢复最近 30 分钟内实际验证成功的节点。
- 只有检测到配置重载时执行恢复；普通手动切换不被覆盖。
- 故障接管同时接受本轮验证过的 `Compatible` 和 `BasicCompatible` 节点。
- 不因地区名称过滤节点，恢复目标仍必须存在于当前候选列表。
- 不重启 Clash，不增加常驻线程或显著内存占用。

## 状态模型

`HealthState` 增加最近稳定选择及验证时间。状态文件继续使用 `CCM1` 头，并增加可选的 `P` 记录，以兼容 v0.1.0 已有状态：

```text
P\t<base64 节点名>\t<UTC ticks>
```

只有当前实际节点完成 `Compatible` 或 `BasicCompatible` 扫描后才更新该记录。订阅候选指纹变化时，已有健康记录会按现有规则失效；因此刚发生结构性订阅变化时不会盲目恢复旧节点。

## 重载恢复流程

1. 通过运行时 IPv6 配置重新出现识别外部配置应用，这是现有监控器已经使用的重载信号。
2. 先恢复 IPv4 兼容覆盖层。
3. 读取当前候选、健康状态及订阅指纹。
4. 仅当最近稳定节点仍在候选中、健康等级可用、验证时间不超过 30 分钟时，将共享选择器恢复到该节点。
5. 立即按正常流程扫描恢复后的实际节点；扫描成功才刷新最近稳定记录。
6. 若没有合格记录则不猜测，保留 Clash 当前选择并进入常规扫描和故障切换。

## 故障接管

`FailoverController` 的替代节点谓词改为同时接受 `Compatible` 与 `BasicCompatible`，同时保留冷却期、两次失败确认、10 分钟最短持有期和本轮新验证要求。地区受限、服务失败、临时失败和未知节点仍不能被选中。

## 可观测性与安全

- 日志记录“检测到配置重载”“恢复成功”或具体跳过原因，但节点名继续使用短哈希。
- 状态文件显示 v0.1.1、实际叶节点和中文决定。
- 不保存订阅 URL、控制器密钥或 Clash 配置内容。
- 部署仍只替换监控器 EXE，升级脚本以 Clash 关键文件哈希确认配置未变。

## 测试与验收

- 状态文件向后兼容、最近稳定选择往返保存。
- 只在重载信号存在时恢复；过期、失效、已移除节点均不恢复。
- `BasicCompatible` 可接管，`Unknown` 和失败等级不可接管。
- 完整离线测试、增强脚本测试、发布安全检查通过。
- 实机升级不重启 Clash，关键配置哈希不变，单进程闲置内存低于 15 MiB。
