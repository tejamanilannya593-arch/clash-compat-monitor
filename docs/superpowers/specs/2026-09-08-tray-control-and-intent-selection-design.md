# 托盘控制与需求驱动选点设计

## 目标

v0.2.0 将 Monitor 从不可见的纯后台进程改为“一次设置、长期自动运行”的托盘工具。用户不需要理解节点质量，也不需要反复在 Clash 中试错：首次选择常用服务后，程序持续寻找同时满足需求、长期稳定且综合体验更好的节点。Clash 的“🌐 统一稳定节点”始终显示实际叶节点名称，Monitor 只在用户主动点开时显示详情。

## 产品行为

- 首次运行显示一次性设置页，默认勾选 Google、GitHub、ChatGPT、Gemini 和 Steam 服务；用户可以修改并保存。
- 保存后进入自动模式。正常状态只驻留托盘，不自动弹窗，也不发送重复通知。
- 双击托盘图标打开详情；关闭详情仅关闭窗口，不停止后台守护。
- 详情展示实际节点、自动模式状态、最近一次决策、下一次复检时间，以及每个已选服务的实测结果和响应时间。
- 详情提供立即复检、暂停或恢复自动优化、恢复上一个节点和退出守护。节点列表与手动选点仍由 Clash 管理，避免两个界面争夺选择权。
- 程序自动应用推荐节点。切换后发送安静的系统通知，并在有限时间内提供恢复上一个节点的入口。
- 第二次启动 EXE 不再静默退出；它向已有实例发送“显示详情”信号后退出。

## 需求与推荐模型

服务偏好是长期配置，不根据浏览历史、前台窗口或进程列表推断，避免隐私风险和误判。已勾选服务的明确失败是候选淘汰条件；通过门槛后继续沿用稳定性、响应与抖动、吞吐和倍率的综合评分。

详情中的“延迟”是对应服务探测端点的 HTTP 响应时间，不宣称等同于真实网页渲染、登录后的生成速度或游戏服务器延迟。Steam 只探测商店、社区和 API；游戏下载及游戏流量继续服从 Clash 现有直连规则，不被 Monitor 导入代理。

自动切换继续遵守以下稳定保护：

- 候选必须在本轮完成所选服务验证。
- 当前节点可用时，目标综合分至少提高 20%，并满足 10 分钟最短持有期。
- 当前节点连续失败后才接管；完全断开时可跳过持有期，但不能跳过候选验证。
- 地区名称不参与通过、失败、优先或降权判断。

## 组件与边界

### 托盘宿主

使用 Win32 通知区域 API 创建低开销托盘图标和右键菜单，负责显示详情、立即复检、暂停或恢复以及退出。托盘宿主不持有检测逻辑，也不等待网络操作。

### 按需详情窗

详情窗使用 WinForms 实现，但只在用户打开时创建，关闭后释放控件和图形资源。界面读取不可变的状态快照，不直接调用 Mihomo，也不阻塞 UI 线程。首次设置沿用同一窗口外壳。

### 后台协调器

现有 `MonitorWorker` 继续负责探测和决策，并运行在独立后台线程。新增协调器接收“立即复检”“暂停”和“退出”命令，发布最新快照给托盘宿主。一次只允许一个检测周期，重复复检请求合并。

### 偏好与状态

在程序本地状态目录持久化服务选择、自动模式开关和首次设置完成标记。写入采用临时文件加原子替换；文件损坏时回退到安全默认服务组合，并在详情中提示，而不是停止守护。

### 单实例唤起

继续使用全局互斥体保证单实例，同时增加命名事件。后启动实例发现互斥体已被占用时触发事件；现有实例收到事件后在 UI 线程显示详情。这样双击快捷方式始终有可见反馈。

## 卡死保护

所有 Mihomo 命名管道操作同时设置连接、写入和读取期限。一次调用超时只使当前周期失败，不能永久占住工作线程。协调器记录周期开始和心跳时间；超过周期上限时将当前周期标记为卡住、通知一次，并允许安全重建客户端或重新启动 Monitor 自身，不重启、不重载 Clash 核心。

退出时先停止接受新检测，给当前操作一个短暂收尾期限，然后释放托盘、互斥体和状态资源。任何异常都写入限长日志，通知和详情中只显示可操作的中文摘要。

## 数据流

1. 托盘宿主加载服务偏好并启动后台协调器。
2. 协调器按周期或用户请求调用 `MonitorWorker`。
3. 扫描器按服务记录可用性、响应时间和失败原因，评分器生成兼容候选排序。
4. 决策器应用稳定保护后，必要时通过 Mihomo 只切换“🌐 统一稳定节点”。
5. 协调器原子发布状态快照；Clash 显示真实节点，详情窗在打开时刷新展示。
6. 正常周期保持安静；切换、无兼容候选、检测卡住或偏好损坏时最多通知一次，状态变化后才允许再次通知。

## 资源约束

- 托盘状态不常驻完整详情窗，不使用内嵌浏览器、WebView、本地 HTTP 服务或数据库。
- 不并发扫描多个节点；沿用最多八个预选候选和有界响应体。
- 托盘空闲工作集目标维持在 15 MiB 左右；详情窗打开后的增量内存必须在关闭后可回收。发布前以实际构建测量，如超出目标则优先减少 WinForms 常驻引用和缓存。
- 状态快照、历史决策和每服务结果均设置固定上限，日志继续限制为 1 MiB。

## 验证

- 单元测试覆盖偏好往返、损坏回退、服务门槛、推荐排序、复检合并、通知去重、超时恢复和单实例唤起协议。
- UI 冒烟测试覆盖首次设置、托盘菜单、详情打开与关闭、暂停与恢复、恢复上一个节点，以及第二次启动唤起详情。
- 故障注入让 Mihomo 管道保持连接但不返回数据，验证周期会在期限内结束，托盘仍可操作，下一轮可以恢复。
- 实机验证 Clash 中实际叶节点与详情一致；节点数量、订阅配置和直连规则不被修改。
- 分别测量仅托盘、详情打开、完整扫描三个阶段的工作集和 CPU；空闲时不持续占用 CPU。

## 非目标

- 不读取浏览历史，不识别当前网站或前台应用。
- 不在 Monitor 中复制完整 Clash 节点管理界面。
- 不提供节点、订阅或游戏 VPN，不把 Steam 网页探测结果描述为游戏加速质量。
- 不重启或重载 Clash 核心来恢复 Monitor。
