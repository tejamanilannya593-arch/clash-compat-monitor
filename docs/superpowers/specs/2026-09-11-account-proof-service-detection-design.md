# v0.6.1 账号实测与严格服务证据设计

## 背景

v0.6.0 已经把 ChatGPT 首页 200、Cloudflare 验证页以及 Gemini 登录重定向明确标记为 `Partial`，但 `ConnectionAssurance.Passed()` 仍将由这些证据形成的 `BasicCompatible` 当作可用。实机日志因此出现了以下错误链路：

1. 当前节点 ChatGPT 连续两次网络异常；
2. 程序执行容灾切换；
3. 新节点只能确认 ChatGPT Cloudflare 页面和 Gemini 登录入口可达；
4. 新节点仍被记录为 `BasicCompatible`，进入备用、评分和保持逻辑；
5. 界面虽然提示“未验证登录及对话功能”，切换策略却已经把它当成通过。

当前状态记录进一步证明，香港 I4 被显示为“基础可用”，但 ChatGPT 和 Gemini 都没有账号级证据。这是证据等级与切换资格混用导致的问题，不是节点名称识别错误。

## 目标

- 入口/CDN 可达不再等于节点可用于自动切换。
- ChatGPT、Gemini 分别获得“入口可达”“登录链路正常”“账号实测通过”三级证据。
- 主动性能寻优只选择近期账号实测通过的节点。
- 故障容灾在没有账号实测备用时仍可工作，但必须标记为临时容灾并严格观察、快速回退。
- 用户通常不需要操作；只有首次建立可信节点、出口变化或明确失败后才需要一次简短确认。
- 不读取或保存浏览器 Cookie、账号、提示词、回复内容。
- 完整移除 JMComic 网页检测。
- 不解析“香港”“日本”等节点名称作决定；实际出口与服务响应才是证据。

## 非目标

- 不自动登录 ChatGPT 或 Gemini。
- 不模拟或绕过 Cloudflare、Google、OpenAI 的验证机制。
- 不调用需要用户 API Key、可能计费的生成接口。
- 不宣称匿名 HTTP 探测可以证明账号一定能够生成内容。
- 不修改 Clash/Mihomo 配置文件或接管订阅。

## 方案选择

### 方案 A：完全匿名自动检测

用户零操作，但只能证明网络和登录入口可达，无法证明账号登录及生成。不能满足“真的可以登录”的要求。

### 方案 B：自动严格筛选，加近期人工账号实测

后台自动检测服务入口、认证链路、实际出口、地区风险和延迟；只有少数需要成为可信节点的候选才请求用户完成一次双服务实测。验证结果本地记忆并自动失效。这是本版本采用的方案。

### 方案 C：内置浏览器和自动化登录

可以减少后续点击，但需要维护浏览器运行时并接触登录态，增加 Cookie 泄露、账号风控、页面变更和资源占用风险。本版本不采用。

## 证据模型

每项服务独立维护以下证据等级：

1. `Reachable`：域名、TLS、CDN 或入口页面有响应，但没有证明认证链路可用。
2. `LoginReady`：服务入口和认证入口均返回预期响应，没有挑战页、明确地区限制或异常重定向；历史延迟达到门槛。
3. `AccountVerified`：用户在当前实际出口下完成一次真实登录及最小生成，并在软件中确认成功。

`Reachable` 对应现有 `Partial` 的语义，只能用于诊断，不能满足以下条件：

- 不能成为主动性能寻优目标；
- 不能进入“可信备用”列表；
- 不能把状态显示为“运行正常”；
- 不能积累成功的稳定历史。

`LoginReady` 是匿名自动检测能够达到的最高等级。它证明登录链路在网络层面可用，但界面必须继续说明其不等于账号级生成成功。

`AccountVerified` 是账号级证据，只能来自用户确认，不能由 HTTP 状态码推断。

## 自动检测

### 实际出口身份

通过现有代理链路访问一个稳定的轻量出口信息端点，取得出口 IP 与国家/地区代码。程序只保存以下内容：

- 使用每次安装生成的本地随机密钥计算出口 IP 的 HMAC-SHA256；
- 国家/地区代码；
- 采集时间。

不保存原始出口 IP，不上传任何监控数据。如果出口信息端点不可用，则证据降级为未知，不根据节点名称猜测。

### ChatGPT

自动探测由独立的应用入口和认证入口组成。实现时优先选择公开、无需凭据且不会产生费用的端点，不依赖生成接口，不绕过挑战页。

判定规则：

- 应用入口和认证入口都必须返回预期状态或可信的同站/官方认证域重定向；
- Cloudflare challenge、仅首页 200、异常重定向均为 `Reachable`；
- 出现 `unsupported_country_region_territory` 等明确响应时为地区失败；
- 实际出口不在随版本发布并注明更新时间的 OpenAI ChatGPT 支持地区快照中时，标记为“地区风险”，不得自动成为切换目标；
- 用户若在该出口完成真实账号实测，可以形成仅对该出口指纹有效的人工覆盖，不把节点名称加入全局白名单。

支持地区快照是保守预筛选，不在运行时抓取或解析网页。版本升级时根据 OpenAI 官方支持地区页面更新。当前官方列表不包含香港，因此香港实际出口默认不能获得 ChatGPT `LoginReady`，但节点标签写“香港”本身不参与判断。

### Gemini

自动探测由 Gemini 应用入口和 Google Accounts 认证入口组成：

- Gemini 页面和 Google 官方认证域必须都可达；
- 精确校验重定向主机，拒绝相似恶意域名；
- 登录重定向本身只证明认证链路存在，必须结合认证入口响应和延迟历史才能达到 `LoginReady`；
- 明确地区或账号资格错误单独分类；
- 账号、Workspace 许可、年龄或风控问题不能归因于节点。

### 延迟门槛

延迟使用首字节时间，不把页面下载、浏览器渲染或模型生成时间混入网络延迟。对 ChatGPT 和 Gemini 的应用、认证入口分别保留历史：

- 至少 5 次成功样本；
- 首个与最后一个样本跨越至少 30 分钟；
- 成功率不低于 95%；
- 各关键入口中位响应不高于 800 ms；
- 最近样本的最慢响应不高于 1500 ms；
- 500 ms 以下显示“优秀”，500–800 ms 显示“良好”，800–1500 ms 显示“可连接但不适合寻优”，高于 1500 ms 不获得低延迟资格。

匿名探测达到上述条件时，界面使用“登录链路低延迟”，不得写成“账号登录成功”或“生成低延迟”。

## 最少操作的账号实测

### 默认流程

用户点击一次“验证当前节点的 AI 服务”：

1. 程序暂停自动切换并记录原节点；
2. 同时用系统默认浏览器打开 ChatGPT 与 Gemini；
3. 对话框提示用户在两个页面各发送一次最小消息，例如“仅回复 OK”；
4. 用户只需在软件中选择“两个都正常”、仅 ChatGPT 失败、仅 Gemini 失败或取消；
5. 程序立即恢复后台监控。

程序不读取浏览器页面，也不自动填写、发送或截取回复。浏览器已有登录态时，用户无需重复登录。

### 记忆与失效

账号实测记录包含订阅连续性范围、节点标识、加密出口指纹、服务、结果和时间，不包含账号信息或对话内容。

成功记录默认有效 30 天，在以下任一情况发生时立即失效：

- 实际出口指纹变化；
- 订阅连续性判定为新订阅或大幅变化；
- 对应服务第一次出现明确地区失败或服务失败；
- 用户主动清除记录；
- 软件升级改变证据规则版本。

普通超时不会立即删除人工记录，但会进入现有连续失败确认流程。

### 降低打扰

- 默认只验证当前节点，不要求用户逐个验证所有候选。
- 已有有效记录时不重复提示。
- 软件不会自动弹出浏览器；故障切换后只发送托盘通知，用户可选择“现在验证”或忽略。
- “验证下一个备用”作为可选操作提供给希望建立人工可信备用池的用户。

## 切换规则

### 当前节点可用时

- 不主动切换到只有 `Reachable` 或 `LoginReady` 的候选。
- 性能寻优候选必须对所需的 ChatGPT、Gemini 都达到 `AccountVerified`，并满足 5 次、30 分钟、95% 和延迟门槛。
- 当前节点只有入口可达时，界面显示“待账号验证”，不显示“运行正常”；在没有明确失败前保持连接，避免因为检测能力不足反复切换。

### 当前节点明确故障时

- 继续执行两次连续失败确认。
- 优先选择近期 `AccountVerified` 的备用节点。
- 没有人工可信备用时，可以选择同时达到 ChatGPT、Gemini `LoginReady` 的候选作临时容灾；界面明确显示“临时容灾，账号未实测”。
- 只有 `Reachable` 的候选不得自动接管。
- 临时容灾切换后第一次明确服务失败就复检旧节点；旧节点通过则立即回退。

### 用户负反馈

托盘菜单增加“当前节点 ChatGPT 不可用”和“当前节点 Gemini 不可用”。用户点击后：

- 立即撤销对应服务的人工成功记录；
- 记录一次明确的本地负反馈；
- 如果当前节点来自最近一次自动切换，立即复检旧节点并按现有安全策略回退；
- 不把该地区或节点名称永久加入黑名单。

## JMComic 移除与兼容迁移

- 从 `ServiceKind`、端点映射、界面、默认设置、状态展示、文档和测试中删除 `JMComicWeb`。
- 旧版首选项中存在字符串 `JMComicWeb` 时静默忽略，下一次保存时清理，不导致启动失败。
- 旧经验记录中包含 JMComic 的服务范围时重新计算范围；保留其他服务的历史，不沿用 JMComic 成功或失败数据。
- 发布说明明确 v0.6.1 起不再提供 JMComic 检测。

## 组件边界

- `HttpServiceProbe`：执行单个公开端点请求并返回原始服务证据，不决定切换资格。
- `ServiceEvidencePolicy`：组合应用入口、认证入口、地区风险和历史延迟，产生三级证据。
- `ExitIdentityProbe`：获取出口信息并生成本地加密指纹。
- `AccountVerificationMemory`：保存、查询和撤销人工账号实测记录。
- `SwitchEligibilityPolicy`：分别判断保持、主动寻优、可信容灾和临时容灾资格。
- `AccountVerificationForm`：引导打开两个网页并收集一次结果，不接触浏览器数据。

证据采集、证据解释、记忆和切换决策必须分离，避免再次出现“提示说未验证，策略却认为通过”的矛盾。

## 状态与诊断

详情页按服务显示：

- 当前证据等级；
- 应用入口和认证入口的中位延迟；
- 最近人工实测时间及剩余有效期；
- 地区风险、挑战页、账号资格或网络失败的不同原因；
- 当前节点是否具备主动寻优、可信容灾或临时容灾资格。

日志继续使用节点哈希。新增日志只记录证据等级、出口指纹前缀、延迟、决策原因和人工确认结果，不记录原始 IP、URL 参数、Cookie 或页面内容。

## 错误处理

- 出口身份、支持地区或认证入口无法确认时返回 `Unknown`，不假装成功。
- 第三方或服务端短时故障继续使用服务事故共识与熔断，不把多个节点的同类失败归因于单节点。
- 浏览器启动失败时保留自动检测结果并给出手动打开链接，不改变节点。
- 用户取消实测时不记失败，也不改变当前节点。
- 旧设置迁移失败时回退到安全默认服务集合，并保留原文件用于诊断。

## 测试策略

采用测试驱动实现，至少覆盖：

- `BasicCompatible`/`Reachable` 不能成为备用或自动切换目标；
- Cloudflare challenge、仅首页成功和仅 Gemini 登录重定向不能达到 `LoginReady`；
- ChatGPT 实际出口为不支持地区时阻止自动切换，节点名称不参与判断；
- 支持地区、双入口和延迟历史同时达标时获得 `LoginReady`；
- 人工实测记录按订阅、节点、出口指纹和证据规则版本绑定；
- 记录在 30 天、出口变化、明确服务失败和规则升级时失效；
- 主动寻优要求 `AccountVerified`，故障容灾可按规则使用 `LoginReady`；
- 临时容灾第一次明确失败触发旧节点复检与回退；
- 旧设置中的 JMComic 被忽略并清理；
- UI 和诊断不再出现 JMComic，且不泄露原始出口 IP 或账号数据；
- 完整构建、单元测试、增强脚本测试、安装与升级测试、发布包检查全部通过。

## 发布范围

该变更作为 v0.6.1 发布。安装验证先在本机完成，再生成 ZIP 与 SHA-256，更新 D 盘成品并发布 GitHub Release。发布说明必须明确：

- v0.6.1 修复的是切换证据过宽，而不是声称自动探测可以替代账号实测；
- 香港节点标签不被硬编码屏蔽，实际出口和官方支持地区证据才参与 ChatGPT 判断；
- Gemini 与 ChatGPT 的地区支持不同，分别判断；
- 账号实测完全本地、无需提供 API Key，不读取浏览器登录数据。
