# v0.6.2 浏览器自动真实对话验证设计

## 背景

v0.6.1 将 ChatGPT、Gemini 的证据分为入口可达、登录链路正常和账号实测通过三层。最后一层需要用户打开网页、发送消息并手动反馈。这个方案没有读取浏览器数据，但把验证操作和判断责任交给了用户，不符合后台守护程序“少操作、少误切”的目标。

v0.6.2 将人工反馈改为可选的浏览器伴侣自动验证：在用户已经登录的 Chrome 或 Edge 中完成一次真实短对话，自动判断结果并关闭测试标签页。程序仍不接管账号密码，不绕过验证码，也不把对话内容交给守护程序。

## 目标

- 自动完成“打开官方页面、发送唯一短消息、确认真实回复、关闭标签页”的闭环。
- 真实对话证据绑定订阅连续性范围、实际节点、加密出口指纹、服务和规则版本。
- 用户只需安装并启用一次浏览器伴侣；之后可从守护程序一键验证，自动容灾切换后也可按授权自动验证。
- 默认保守：当前节点仍可用时不做性能寻优切换。
- 不安装伴侣时，现有网络链路检测和故障容灾继续工作，但界面不宣称真实对话已经验证。
- 不读取或保存用户账号密码、Cookie、普通聊天内容或浏览历史，不上传遥测。

## 非目标

- 不自动输入账号、密码、短信验证码、二次验证或验证码答案。
- 不绕过 Cloudflare、Google 或服务方的登录与风控机制。
- 不使用 ChatGPT、Gemini 的未公开后端接口。
- 不定期对全部候选节点发送真实消息。
- 不自动删除测试对话；网页结构变化时，自动删除存在误删正常聊天的风险。
- 不用 OpenAI API 或 Gemini API 的结果冒充网页版可用性证明。

## 方案比较

### 方案 A：Windows UI Automation 或 Playwright 控制现有浏览器

可以直接操作页面，但需要调试端口、用户配置目录或桌面焦点，容易干扰用户，浏览器升级后也较脆弱。访问现有浏览器会话的权限边界不清晰，不采用。

### 方案 B：程序内嵌 WebView2

状态机最容易控制，但需要用户在独立浏览器环境重新登录；嵌入式身份验证还可能受服务方限制。它不能复用用户常用浏览器的登录状态，不采用。

### 方案 C：Manifest V3 浏览器伴侣加本机 Native Messaging

扩展只在 ChatGPT 和 Gemini 的官方站点运行，复用用户已有登录会话。守护程序与扩展通过允许来源固定的本机消息宿主通信，网页 Cookie 不离开浏览器。该方案一次安装后操作最少，权限与数据流也最容易审计，因此采用。

## 用户体验

### 首次启用

1. 用户从发布包或浏览器商店安装同一份 Chromium Manifest V3 扩展；Chrome 与 Edge 共用代码。
2. 安装器按当前用户注册 Native Messaging 宿主，不需要管理员权限。
3. 详情页显示伴侣状态和明确权限说明。用户主动开启“自动真实对话验证”，形成持久的本地授权。
4. 如果浏览器尚未登录某项服务，扩展只返回“需要登录”。程序提示一次，不循环打开页面。

### 一键验证当前节点

1. 用户点击“自动实测当前节点”。
2. 守护程序确认伴侣在线，冻结当前节点、出口指纹和服务范围，并暂时暂停自动切换。伴侣离线时只提示用户打开已安装扩展的浏览器，不直接打开普通网页。
3. 扩展依次打开 ChatGPT 和 Gemini 官方页面，每次只处理一个服务。
4. 扩展发送包含高熵随机校验码的固定消息，例如“只回复 `CCM-A7F2`”。
5. 扩展等待新的助手回复，并仅判断该回复是否包含本次校验码。
6. 成功、明确失败或超时后关闭测试标签页，再处理下一项服务。
7. 守护程序重新确认节点和出口未变化后才保存结果，并恢复此前的暂停状态。

测试对话会保留在账号历史中。界面在用户启用功能前明确说明这一点。同一服务、节点和出口的成功证明有效 30 天，期间不会重复发送。

### 自动切换后的验证

- 只有用户已启用自动真实对话验证且伴侣近期在线时，容灾切换后才创建自动任务。
- 浏览器暂未运行时只保留一次待验证意图；下次伴侣上线后才生成 5 分钟有效的具体任务，不反复拉起浏览器窗口。
- 任务只验证已经接管的当前节点，不扫描或轮流切换全部候选节点。
- 成功后记录真实对话证明。
- 如果消息已经成功发出，但服务返回明确错误或在生成阶段超时，则复检旧节点；旧节点通过时立即回退。
- 未登录、验证码、扩展离线或页面结构不受支持属于“无法验证”，不能直接归因于节点，也不能据此切换或回退。

## 默认切换策略

- 默认模式下，只要当前节点仍满足可保持条件，就不因延迟、速度或综合分主动切换。
- 当前节点明确故障时，继续采用连续失败确认、严格候选证据、切换观察和旧节点复检。
- 高级性能寻优必须由用户主动开启，并同时要求真实对话证明、至少 5 次跨 30 分钟且成功率不低于 95% 的历史、中位延迟不超过 800 ms、单次和单服务不超过 1500 ms、抖动不超过 150 ms，以及至少 20% 综合提升。
- v0.6.1 的人工反馈记录不再满足 v0.6.2 的真实对话证明要求；升级后不会把旧人工判断当作浏览器自动闭环。

## 组件与边界

### 浏览器扩展

- `manifest.json`：Manifest V3，使用固定公开密钥得到稳定扩展 ID，只申请 `nativeMessaging`、生命周期所需权限，以及 `https://chatgpt.com/*`、`https://gemini.google.com/*` 的精确主机权限。
- 后台 service worker：在浏览器启动、扩展安装和工作线程唤醒时连接 Native Messaging 宿主；接收开始任务、按顺序创建测试标签页、转发结果、保证同一时间只有一个任务。
- ChatGPT 与 Gemini 站点适配器：定位输入框、提交固定消息、识别新回复、登录页、验证码、明确错误和页面结构变化。
- 适配器只向后台返回枚举结果、耗时和校验码是否匹配，不返回 DOM 文本。

扩展技术上必须检查测试标签页中的新回复才能匹配校验码。这个读取只发生在扩展自己创建的测试标签页中，普通标签页不执行内容提取；读取结果不落盘、不上传，也不发送给守护程序。

### Native Messaging 宿主

- 使用单独的 `ClashCompatibilityMonitor.BrowserHost.exe`，避免浏览器启动宿主时误创建第二个托盘实例。
- stdin/stdout 只承载带长度前缀的 JSON 消息；stdout 不写日志或诊断文本。
- 宿主在扩展连接存续期间保持运行，在浏览器消息流与守护程序专用命名管道之间做双向桥接；任一端断开后安全退出，由扩展按有上限的退避策略重连。
- 输入限制大小、消息类型、字段长度和服务枚举，拒绝未知来源、过期任务和重复结果。
- 宿主通过当前用户可访问的专用命名管道与运行中的守护程序通信。
- Chrome 和 Edge 的宿主清单只允许发布扩展的固定 ID；安装器写入当前用户注册表项，卸载时只移除本软件创建的项。

### 守护程序

- `BrowserVerificationCoordinator` 管理授权、伴侣在线状态、任务生命周期、限频和节点/出口冻结。
- `BrowserVerificationTask` 包含任务 ID、服务、节点、出口指纹、随机校验码、创建时间和到期时间，不包含账号或代理凭据。
- 结果状态为 `Passed`、`ConversationError`、`GenerationTimeout`、`SignInRequired`、`ChallengeRequired`、`AutomationUnsupported`、`Cancelled`。
- 只有 `Passed` 写入正向证明；只有已经发送成功后的明确对话错误可触发旧节点复检。其他结果保持未知。

## 通信与安全

- 每个任务使用至少 128 位随机 ID，并在 5 分钟后失效。
- Native Messaging 来源必须与固定扩展 ID 完全匹配。
- 扩展提交结果时必须带任务 ID、服务和随机校验码；守护程序还会比对冻结的节点与出口指纹。
- 同一任务只接受一次终态结果，重放消息不会重复写入证明或触发回退。
- 本机消息正文上限 64 KiB；页面文本、Cookie、HTML、账号标识、用户提示词和回复不会进入协议，协议中只允许程序生成的随机校验码。
- 扩展不申请 `cookies`、`history`、全站访问或远程代码权限。
- 自动真实对话验证默认关闭；授权、关闭和清除证明均在本地完成。

## 限频与生命周期

- 成功证明在节点和出口不变时有效 30 天。
- 单项服务失败或无法验证后至少冷却 6 小时，除非用户主动重试。
- 同一时刻最多一个浏览器验证任务。
- 每次自动切换最多验证一次，不因普通后台扫描创建真实对话。
- 浏览器或守护程序退出时任务变为取消，不记录失败。
- 节点、出口、订阅范围或检测规则在任务期间变化时，结果作废。

## 错误处理

- 未登录或出现验证码：关闭自动创建的标签页，提示用户在常用浏览器完成登录；不撤销已有节点历史。
- 页面结构变化：记录 `AutomationUnsupported`，保留网络检测结果并提示更新扩展。
- 扩展或宿主不可用：取消任务并恢复守护程序状态，不影响故障容灾。
- 页面加载失败：结合守护程序同一时刻的严格网络探测；只有两者都指向节点故障时才进入故障确认。
- 回复不包含校验码：视为无法确认，不把任意旧回复误判为成功。
- 用户关闭标签页：视为取消，不生成负面证据。

## 数据迁移与显示

- `AccountVerificationRecord` 增加证明方法和协议版本；旧记录读取兼容，但不能满足自动真实对话证明门槛。
- 状态文案改为“网络链路兼容”“真实对话已验证”“需要浏览器登录”或“浏览器自动化暂不支持”，不再要求用户选择“正常/失败”。
- 删除 v0.6.1 的人工成功/失败按钮；保留撤销证明和主动重试入口。
- 状态与日志只使用哈希节点标识，不记录测试消息、回复或账号信息。

## 测试策略

### C# 自动测试

- 任务创建、5 分钟过期、单终态、重放拒绝、节点与出口漂移失效。
- 30 天成功限频、6 小时失败冷却、默认保守模式和高级寻优门槛。
- Native Messaging 长度前缀、消息大小、枚举与字段校验。
- 未登录、验证码和页面不支持不归因于节点；明确对话失败触发旧节点复检。
- 安装、升级和卸载仅修改本软件目录及当前用户 Native Messaging 注册项，不修改 Clash 配置。

### JavaScript 自动测试

- 两个站点适配器的成功、登录、验证码、明确错误、超时、用户取消和 DOM 变化场景。
- 只接受本次新回复中的完整随机校验码，不接受页面已有内容或部分匹配。
- 任务结束始终关闭扩展创建的标签页。
- 权限审计确保没有 Cookie、历史、全站主机或远程代码权限。

### 发布与实机验证

- 发布包包含扩展、Native Messaging 宿主、两种浏览器宿主清单和安装说明。
- 自动测试不使用真实账号。实机冒烟测试必须由用户明确触发，并在已登录账号中产生一条可见的短测试对话。
- 完整构建、逻辑测试、扩展测试、发布测试、安装自检及 Clash 配置前后哈希比较全部通过后才能发布。

## 发布边界

v0.6.2 可以随 ZIP 提供可审计的未打包扩展和安装说明。浏览器商店发布需要独立的开发者账号与审核，不作为本地代码完成的前置条件；在商店版本可用前，界面不得声称扩展能零操作安装。
