# Z-Library 网页入口检测设计

## 目标与边界

- 使用用户指定的 `https://zh.z-library.sk/`，不搜索、更换或推荐其他域名。
- 新增默认关闭的“Z-Library 网页”服务选项。只有用户勾选后，才在既有节点检测流程中请求该入口，并将检测结果用于节点适配判断。
- 检测范围仅为网页入口的网络可达性和响应时间；不登录、不搜索、不下载、不收集账号信息，也不声称已验证这些功能。
- 该功能作为 v0.6.2 之后的独立变更；不覆盖已交付的 v0.6.2 包。

## 方案选择

采用单一、固定的用户指定 HTTPS 入口和现有轻量 HTTP 探测。相比仅以任何 2xx/3xx 认定成功，本方案区分正常入口、验证页、异常跳转和明确失败；相比浏览器登录验证，本方案无需账号操作且后台开销较小。域名变动时不自动追踪镜像，避免误连到仿冒站。

## 行为

1. 设置界面新增独立选项；现有用户的已保存服务选择保持不变，新安装默认不启用。
2. 勾选后，每个被评估节点使用现有代理出口、超时和响应体上限访问指定 HTTPS URL。未勾选时不发出该服务请求。
3. HTTP 200 且未识别到验证页或地区阻断时记为“入口可达”，记录响应头到达的延迟；这仅证明本次入口请求得到正常 HTTP 响应，无法可靠识别仿冒页面。已知验证页、验证码、登录挑战和任何 HTTP 重定向记为“仅确认可达”，不自动跟随跳转。超时、网络错误、明确地区阻断及其他 HTTP 错误记为失败。
4. “入口可达”满足此服务的节点适配条件，但界面不得把它写成“登录/搜索/下载可用”；“仅确认可达”沿用现有部分证据策略，不能成为已验证的容灾目标。既有连续失败、备用节点和保守切换规则不变。
5. 检测结果显示在状态表，服务名明确为“Z-Library 网页”。说明文档注明检测边界和站点地址可能失效。

## 实现范围与验证

- 在服务枚举、端点与响应分类、设置选项、状态文案和用户文档中做必要的最小改动；不修改 Clash 配置文件。
- 先写失败测试，覆盖：默认关闭、选中后持久化并参与扫描、正确端点、正常入口与验证页的区别、异常跳转及失败响应、显示文案不夸大功能。
- 运行完整构建、现有 JS 测试和发布检查；若环境能访问该地址，再做只读实测。网络实测失败不等于代码失败，应分别报告。

## 已知限制

- 当前外部网页抓取未能打开用户指定地址，因此不能在设计阶段验证该站点当前的页面结构或长期可用性。实现不依赖不稳定的页面文案，也不将一次外部抓取失败归咎于用户节点。
- 即使入口请求成功，也不能保证账号登录、图书搜索或下载成功。
