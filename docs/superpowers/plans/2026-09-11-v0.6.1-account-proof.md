# v0.6.1 Account-Proof Service Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent CDN-only ChatGPT/Gemini evidence from qualifying nodes for automatic switching, remove JMComic, and add a low-friction local account-verification workflow.

**Architecture:** Keep raw HTTP probing, evidence interpretation, account-verification memory, and switch eligibility separate. Extend candidate scans with an encrypted exit fingerprint and country code, treat `BasicCompatible` as hold-only, and require `Compatible`/`LoginReady` for emergency failover plus recent `AccountVerified` evidence for proactive quality switching.

**Tech Stack:** C#/.NET Framework 4.x, Windows Forms, `HttpClient`, `System.Web.Script.Serialization`, PowerShell release scripts, the existing executable test harness.

public static class ServiceEvidencePolicy

- [ ] **Step 3: Implement exit identity primitives**

Create `src/ExitIdentity.cs` with immutable `ExitIdentity`, strict trace parsing, and HMAC-SHA256:

```csharp
public sealed class ExitIdentity
{
    public ExitIdentity(string fingerprint, string countryCode, string detail)
    { Fingerprint = fingerprint ?? ""; CountryCode = countryCode ?? ""; Detail = detail ?? ""; }
    public string Fingerprint { get; private set; }
    public string CountryCode { get; private set; }
    public string Detail { get; private set; }
    public bool Known { get { return Fingerprint.Length > 0 && CountryCode.Length == 2; } }
}
```

`ExitIdentityParser.Parse` must require both `ip` and a two-letter `loc`, compute uppercase hex HMAC, and never retain the raw IP. `ChatGptSupportedRegions` must contain the ISO country codes corresponding to the OpenAI ChatGPT supported-country page snapshot dated 2026-09-11; unknown codes return false.

- [ ] **Step 4: Implement raw multi-endpoint probing**

Add `LoginRedirect` to `ProbeFailureKind` and `ProbeResult.LoginRedirect`; it is an intermediate raw endpoint result, never a final candidate result. Refactor `HttpServiceProbe.Probe` so ChatGPT and Gemini call an application endpoint and an authentication endpoint within the caller's total timeout. Use:

```csharp
case ServiceKind.ChatGPT:
    return ProbeLoginChain(service, Endpoint(service), new Uri("https://auth.openai.com/"), timeout);
case ServiceKind.Gemini:
    return ProbeLoginChain(service, Endpoint(service), new Uri("https://accounts.google.com/"), timeout);
```

Keep redirects disabled and exact-host checks. A ChatGPT application 200 is a raw success; a Cloudflare challenge is partial. A Gemini redirect is `LoginRedirect` only when its absolute HTTPS host is exactly `accounts.google.com`. `CombineLoginChain` returns success for two raw successes, or for Gemini's exact `LoginRedirect` plus a successful Google Accounts response. A challenge, generic partial page, untrusted redirect, or unknown response returns `Partial`; explicit region, service, and transient failures retain their classification. Total elapsed time is the sum of both endpoint measurements.
